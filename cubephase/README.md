# 放方块单测：π0 全任务里的方块那一半（时间重参数化）

**要解决的问题**：用户要求"就算抽屉没拉开，方块臂也要把方块夹住放进去"。

那个"必须先拉开抽屉"的限制**不是代码**，是 π0 策略学到的时序程序——活机器上它
只在抽屉臂松爪后 1.97 s 才让方块臂起动。唯一真做法是**把 π0 在这一相位该做的动作
单独发给 can0**，绕开策略内部的相位门控。

但"原样放"过不去执行链，见下。本目录是修好之后的那一版，也就是 π0 完整任务里
"把蓝方块放进抽屉"那一步的单测。

**真机账目**：本段目前只有离线自测（`test_replay.py`）与干跑，**真机还没跑过**。
干跑报告里逐字是 `result = dryrun_passed_no_commands`（`SDK was not initialized`，
一行命令没发、电机没使能）。

## 一、为什么"原样放"不行

执行链每拍压步长：

| 层级 | 关节 | 夹爪 |
|---|---|---|
| 客户端 `limited_target`（`PI0_JOINT_RATE`/`PI0_GRIPPER_RATE`） | 0.40 rad/s | 0.030 m/s |
| 驱动护栏 `verified_hardware.py:474/476`（`.25*dt+.01` / `.006*dt+.001`） | 0.01833 rad/拍 | 0.00120 m/拍 |

而演示那一夹是快的（`today99` 全部 86 集实测）：

| 轴 | 语料单拍峰值 | 超客户端帽 | 超驱动护栏 |
|---|---|---|---|
| 方块臂 rJ2 | 0.07471 rad | 5.6× | 4.1× |
| 方块臂 rJ3 | 0.04789 rad | 3.6× | 2.6× |
| 方块爪 rjaw | 0.01240 m | **12.4×** | **10.3×** |

**86/86 集全超。** 限速器把"加速冲过去、到点停住"切成斜坡，于是**手臂到位和合爪
被拉成两条时间线**：

| 设置 | 手臂 rJ2 到位 | 爪合到 0.060 | 错位 |
|---|---|---|---|
| 语料（演示本身） | 第 109 拍 | 第 109 拍 | 0 拍 |
| 现链路 0.40 / 0.030 | 第 146 拍 | 第 240 拍 | +94 拍 = 3.13 s |
| 方块项目复位档 0.80 / 0.010 | 第 108 拍 | 第 284 拍 | +176 拍 = 5.87 s |
| 驱动护栏极限 0.55 / 0.036 | 第 118 拍 | 第 236 拍 | +118 拍 = 3.93 s |

抬 `joint_rate` 修不了：驱动护栏只给 0.01833 rad/拍，而语料要 0.059 ——
抬上去整跑会被 `Joint command slew exceeds` 打断。

## 二、本目录的做法：协调时间重参数化

把整段轨迹重采样到**一条共享的参照时刻 s** 上，14 个轴永远处在同一个 s；
每拍只把 s 推进到"最慢的那一根轴允许的最大值"（`make_traj.py` 的
`coordinated_stretch`）。于是：

- **相对时序逐字保住** —— 演示里"手臂到位"和"合爪"落在同一参照时刻，重采样后仍然如此。
- **每拍步长被压到帽内** ⇒ 客户端 `limited_target` 变成**空操作**，发什么就是什么。
- **不碰任何安全阈值**，不改客户端一个字节。

代价是时间变长（实测 **1.68 倍**，14.7 s → 25.0 s）。对这件事无害：
**方块不会动**，慢一点照样夹得到。

## 三、本目录与客户端（`../shared/pi0_real_trial_v8.py`）的关系

客户端**逻辑完全不动**。启动器把 `TRIAL` 指向 `../shared/pi0_real_trial_v8.py`
（机器上那份活客户端的改名版：逻辑一字未改，只把名字前缀换成了 pi0_），只把 `--url` 指到本目录的本地服务端。所以：

| 部件 | 来源 |
|---|---|
| 客户端闸门 / 限速 / 跟踪校验 / 归位 / 报告 / trace | `../shared/pi0_real_trial_v8.py`（活客户端的改名版，逻辑一字节未改；真机跑 π0 策略用的就是它） |
| 服务端 | 本目录 `replay_server.py`（按序列回答 `/infer`；换成 π0 策略服务，跑的就是策略本身） |
| 轨迹 | 本目录 `cube_phase_traj.npz`（`make_traj.py` 生成，只读语料） |

## 四、服务端三条自己的约定

1. **抽屉臂（槽 0..6）不发轨迹，钉在起跑位姿前 7 维**。它停在归位点上不动。
   （早期版本是"回声它自己的实测位姿"——那等于把限速器接成一个带增益的反馈环，
   跟踪误差会让手臂慢慢爬走。）
2. **arming 判据只比方块臂那 7 维** + 抽屉臂 J2 钉 home：`L∞((state-state0)[7:14]) < 0.25`
   且 `|state[1] - home[1]| < 0.06`。只比全 14 维会**永远不成立**——演示第 0 拍抽屉臂
   还夹在抽屉拉环上（离 home 0.207 rad）。第一次匹配的请求才把游标置 0（被动 peek 因此
   被干净地排除）。到 20 次仍未 arm 就回 error 让 trial 中止，而不是静默按着不动。
3. **轨迹首部前置 10 拍保持不动**。若被动 peek 恰好也在归位位姿上，第一个 10 行块会被
   peek 吃掉，前置行让这种"跳掉 10 行"退化成无害的 0.33 s 静止。

## 五、怎么跑

```bash
cd /home/databall/pi0_infer_3090/cubephase

# 1) 离线自测（无 CAN、无相机、不连机械臂）
/home/databall/miniconda3/envs/lerobot_v30/bin/python -I test_replay.py

# 2) 干跑（电机不使能）
bash run_replay.sh dry-run

# 3) 真机（**由你自己按**）
bash run_replay.sh motion 12     # 先小窗口：只看下探 + 抓取，约 12 s
bash run_replay.sh motion        # 全段，窗口自动取 32 s
```

端口默认 `18312`。若被别的服务占了，脚本会告诉你换一个：
`PI0_PORT=18313 bash run_replay.sh motion`。
**真机模式会先停掉端口上本段的服务端再重起**——服务端是有状态的，游标走过就不回头，
干跑一次会把游标带到末尾，复用就等于每拍只发末行。

旋钮（都是客户端原版的环境变量，脚本会核对）：

| 变量 | 值 | 为什么必须锁死 |
|---|---|---|
| `PI0_JOINT_RATE` | 0.40 | 轨迹是照着这个数把每拍压进帽的 |
| `PI0_GRIPPER_RATE` | 0.030 | 同上 |
| `PI0_ACTION_ALPHA` | 0.25 | 轨迹对多个 α 都验过限速器不动手 |
| `PI0_PRELIFT_RAD` | 0 | prelift 的 +0.30 rad 是把两条臂推出语料的那 0.30 rad |

前两个对不上时脚本直接 FAIL。

## 六、产物与自检

`make_traj.py` 建轨迹时会跑四项自检，任何一项不过就**不产出文件**：

| 自检 | 判据 | 本次实测 |
|---|---|---|
| 每拍步长进帽 | 0 拍超关节/夹爪帽 | 关节 max 0.01200/0.01333，夹爪 max 0.00090/0.00100 |
| 不越 LOW/HIGH | 0 行越界 | 0 行（拉伸的插值残差 3e-10 已先断言后夹回） |
| `limited_target` 实切 | <1e-12（真被切是 1e-3 量级） | **2.17e-19** |
| 不撞驱动护栏 | 比值 <1 | 关节 65%、夹爪 75% |
| 爪合上那拍手臂在演示抓取位 | ≤0.02 rad | **0.0051 rad** |

`ARTIFACTS.md5` 只覆盖源文件（6 个）。轨迹是生成物，它的完整性由服务端启动横幅里的
`PI0_REMOTE_SHA256` 和客户端报告里的 `remote_checkpoint_sha256` 互证。

## 七、已知风险（跑之前必须知道）

**抽屉臂停在归位点不动，方块臂按演示轨迹伸向抽屉——两条臂的相对几何与演示不同。**
离线没法证明它们不碰。所以：手放急停上；第一次先跑 `motion 12` 只看下探+抓取；
`--rollout-seconds` 到点就停写，手臂停在当时的目标上。

本目录**不动**：π0 权重（在 3090 的推理根下，本仓不含）、数据集、归一化统计、
控制参数、任何安全检查阈值；不碰 CAN、相机；不停别的会话的任何进程。
