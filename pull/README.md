# 拉抽屉单测：π0 全任务里的抽屉那一半（时间重参数化）

**要回答的问题**：机器自己能不能把抽屉拉开？
（π0 要做的完整任务是"两条臂都动、抽屉臂自己拉开 + 方块臂把方块放进去"；那一步之前，
先单独验抽屉这一半。这一半不成，合成版一定不成。）

做法：把 π0 在这一段里该动的那串动作逐拍发给机器。本段自带的本地服务端按序列回答；
换成 3090 上的 π0 策略服务，同一份客户端跑的就是策略本身。
源 = `drawer_today99_v1` / `episode_000041` 第 **48..300 拍**（8.43 s）。

## 一、这一段里发生了什么（实测，来自语料本身）

| 段内拍 | 绝对拍 | 事件 | 实测 |
|---|---|---|---|
| 0–62 | 48–110 | 伸手到**关着的**抽屉前 | lJ2 0 → 0.215 |
| 62–115 | 110–163 | 停住、然后大幅调整手腕把爪送到拉环上 | lJ2 → 1.505，lJ4 0.257 → −0.813 |
| 115 | 163 | 爪张到全开 | ljaw **0.0700** |
| 166 | 214 | 爪合到底 ＝ **咬住拉环** | ljaw **≤0.01** |
| 172–222 | 220–270 | **拉** | lJ2 1.505 → 1.075（0.43 rad，按前臂半径折算 ≈ **11 cm**） |
| 232–242 | 280–290 | 松开 | ljaw → 0.0589 |
| 242–252 | 290–300 | 停住 | 全段静止 |
| （段外） | 333 | 方块臂才起动 | 所以段终点取 300 |

最后一行是关键：**方块臂在这一段里逐字不动（偏离首行 0.00000 rad）**，所以段终点取
300 而不是 347 —— 这个测试只动抽屉臂，方块臂一动不动。构建脚本会断言这一条
（>0.01 rad 就直接不产出文件）。

## 二、为什么不能"原样放"

执行链每拍压步长：

| 层级 | 关节 | 夹爪 |
|---|---|---|
| 客户端 `limited_target`（`PI0_JOINT_RATE`/`PI0_GRIPPER_RATE`） | 0.01333 rad/拍 | 0.00100 m/拍 |
| 驱动护栏 `verified_hardware.py:474/476`（`.25*dt+.01` / `.006*dt+.001`） | 0.01833 rad/拍 | 0.00120 m/拍 |

这一段自己的单拍峰值：

| 轴 | 段内单拍峰值 | 超客户端帽 | 超驱动护栏 |
|---|---|---|---|
| 抽屉臂 lJ4（第 133→134 拍） | 0.04780 rad | 4.0× | 2.6× |
| 抽屉臂 lJ2（快速段） | 0.0144 rad/拍 | 1.2× | — |
| 抽屉爪 ljaw | 0.01560 m | **15.6×** | **13.0×** |

限速器把"冲过去、到点停住"切成斜坡 ⇒ **咬住那一拍与手臂到位被拉成两条时间线**。
对这一段最要紧的正是这里：爪必须**在手臂停在拉环上的那一拍**咬住 ——
早一点咬空，晚一点手臂已经越过去了。这与 cubephase 那份修掉的是同一个病。

这一段的物理过程已由**抽帧核对**过（只读语料，未碰活相机）：抽屉爪在 202–220 拍
从全开合到 0.0029 m，并在 218–279 拍一直保持 0.0026–0.0032 m —— 两指之间
**夹着约 3 mm 厚的东西**，是真夹住，不是空合；抽屉约 230 拍开始动、290–300 拍拉到
位置；拉环是**抽屉自己的把手**（不是另摆的圈），臂做完拉的动作后在 282–294 拍松开、
停在抽屉前不动。

## 三、做法：协调时间重参数化

把整段重采样到**一条共享的参照时刻 s**：14 个轴永远处在同一个 s，每拍只把 s 推进到
"最慢的那一根轴允许的最大值"（`make_pull_traj.py` 的 `coordinated_stretch`）。于是：

- **相对时序逐字保住** —— 演示里"手臂停住"和"咬住"在同一个参照时刻，重采样后仍然如此。
- **每拍步长被压到帽内** ⇒ 客户端 `limited_target` 变成**空操作**，发什么就是什么。
- **不碰任何安全阈值**，不改客户端一个字节。

代价是时间变长（实测见构建输出，约 1.8 倍，8.4 s → 约 15 s）。对这件事无害：
**抽屉不会动**，慢一点照样咬得住。

## 四、与 `../cubephase` 的三处不同

| 项 | cubephase 那份 | 这一份 |
|---|---|---|
| 两条臂 | 抽屉臂**钉在归位点**不动（它要动的是方块臂） | **两条臂都按轨迹发**（这里动的就是抽屉臂） |
| arming 判据 | 只比方块臂 7 维 + 抽屉臂 J2（演示第 0 拍抽屉臂还夹着拉环，比 14 维永不成立） | **比全 14 维**，容差 `0.10` |
| 复位目标 | 抽屉**拉开**、爪松开那一位姿 | **抽屉关着、爪合到底**的演示起跑位姿 |

复位目标由 `make_pull_traj.py` 从**同一行**生成（`home_target_pull.json` 的 `target`
＝ 轨迹的 `state[0]`）。三处互相印证：启动器核 `json ↔ meta`，服务端启动时核
`meta ↔ npz.state[0]`，离线测试把三处一起核。链路是：
`json.target == meta.reset_target == npz.state[0]`。

## 五、arming 容差为什么是 0.10

- 客户端复位（`hardware.home` ＋ `settle_home`）只保证**关节 0.035 rad / 夹爪 0.004 m
  且连续稳 0.5 s**，不达标直接抛错。所以判据必须比 0.035 松 —— 0.10 有约 3 倍余量。
- 被动 peek 发生在复位**之前**（手臂还在上一轮停的地方）。这个测试第一轮跑完停在
  **轨迹末行**，它离起跑位姿 lJ2 差 **1.07 rad**，远大于 0.10 ⇒ 不会误触发。
  （万一真的误触发，前置 10 拍"保持不动"把它退化成 0.33 s 静止。）
- 判据松到 0.25 就危险了：那是 cubephase 那份为"比 7 维"才用的宽容差。

## 六、怎么跑

```bash
cd /home/databall/pi0_infer_3090/pull

# 1) 离线自测（无 CAN、无相机、不连机械臂）
/home/databall/miniconda3/envs/lerobot_v30/bin/python -I test_pull.py

# 2) 干跑（电机不使能）
bash run_pull.sh dry-run

# 3) 真机（**由你自己按**）
bash run_pull.sh motion
```

端口默认 `18313`（不碰 18030/18031/18032 那几个别的会话，也不碰 cubephase 的 18312）。
真机模式会**先停掉本段的服务端再重起** —— 服务端是有状态的，游标走过不回头。

旋钮（客户端原版的环境变量，脚本会核对）：`PI0_JOINT_RATE=0.40`、`PI0_GRIPPER_RATE=0.030`、
`PI0_ACTION_ALPHA=0.25`、`PI0_PRELIFT_RAD=0`。前两个与构建值对不上直接 FAIL。

### 真机前的工作区准备

1. **抽屉完全关上**（这一版就是让机器自己拉开）。
2. **爪里不要留东西**。要夹的**拉环就是抽屉正面左上那个黑色把手**，是抽屉自己带的，
   不用另摆、也没有"摆布圈"这件事。
3. **蓝方块留在圆盘上**（这一段方块臂不动）。
4. **两手离开工作区**。

### 跑起来会看到什么

1. 相机核对 → 被动 peek（手臂不动）→ **复位**：两条臂一起开到演示起跑那一拍的位姿。
   抽屉臂主要跨 lJ2 约 **1.0 rad**（限速 0.0133 rad/拍 ⇒ 至少 75 拍 ≈ 2.5 s，还要稳 0.5 s）。
2. 动作：伸手（很快）→ 停 → 调手腕 → 张爪 → **咬住** → **拉** → 松开 → 停。
   咬住落在拉伸后的第 `pipeline_grip_tick` 拍（启动器会打印），总长约 15 s。
3. `REPLAY_ARMED` / `REPLAY_DONE` 会出现在服务端日志里，脚本末尾会打印 ARM 与判读。

**判据只有一条：抽屉有没有真的被拉开。** 报告不看画面。脚本末尾的判读会给：
实测抽屉爪的范围与咬住拍、两条臂各自的首末位移（这一段应当是**抽屉臂大动、方块臂 ≈0**）。

## 七、产物与自检

`make_pull_traj.py` 建轨迹时跑三项自检，任何一项不过就**不产出文件**：

| 自检 | 判据 | 本次实测 |
|---|---|---|
| 每拍步长进帽 | 0 拍超关节/夹爪帽（两个夹爪都算） | 见构建输出 |
| 不越 LOW/HIGH | 0 行越界 | 0 行（插值残差先断言后夹回） |
| `limited_target` 实切 | <1e-12（真被切是 1e-3 量级） | 见构建输出 |
| 不撞驱动护栏 | 比值 <1 | 见构建输出 |
| 咬住那拍抽屉臂在演示位 | ≤0.02 rad | 见构建输出 |
| 段内方块臂不动 | ≤0.01 rad | 0.00000 |

`ARTIFACTS.md5` 覆盖 6 个源文件（含 `home_target_pull.json`，它由构建脚本生成）。
轨迹是生成物，它的完整性由服务端启动横幅里的 `PI0_REMOTE_SHA256` 和客户端报告里的
`remote_checkpoint_sha256` 互证。

## 八、已知风险（跑之前必须知道）

- **复位是一条关节空间直线**（客户端 `hardware.home` 的实现），跨度 lJ2 约 1.0 rad。
  演示里**没有**这条路线（演示只有"从起跑位姿往前走"那一条），所以离线**证不了**
  这条直线中途不碰抽屉。第一次跑：手放急停上；可以先 `dry-run` 看复位目标对不对。
- 复位结束时**抽屉爪是合到底的**（目标里 ljaw = 0.0002），而它最后停在抽屉把手附近。
  拉环是固定在抽屉上的金属件，夹不跑；要紧的是别让合着的爪**顶到**抽屉面板 ——
  这也是第一条"手放急停上"的另一半原因。
- 这一段**不管方块臂**：方块臂全程不动是设计，不是坏了。
- `--rollout-seconds` 到点就停写，手臂停在当时的目标上。
